학습 · 와이어시트 읽기

와이어시트 읽기 로직

이 장의 각 학습 자료에서는 블록 계열 하나씩을 설명했습니다. 이 페이지에서는 그 블록들이 모여 수행하는 일을 설명합니다. 장치는 오작동하고, 프로그램은 다른 사람이 작성했으며, 눈앞의 시트는 모든 배선에 현재 값이 표시되는 실시간 상태입니다. 이런 시트를 재미로 읽는 사람은 없습니다. 무언가 잘못되었기 때문에 읽습니다. 처음부터 끝까지 필요한 기술은 한 가지 질문으로 요약됩니다. 직접 작성하지 않은 프로그램에 문제가 생겼을 때, 실시간 를 어떻게 읽어 잘못된 답을 내는 블록을 찾을까요?

이 페이지는 앞선 학습 자료를 이해했다고 가정합니다. 기능 블록 기초에서 핀, 배선, 스캔을 설명했고, 각 블록 계열인 래치, 비교기, 타이머, 설정값 연산은 저마다의 일상적인 역할을 수행합니다. 두 작업의 경계도 분명히 해야 합니다. 커미셔닝(기능 성능 검증)은 올바른 프로그램이 설치되었음을 입증합니다. 포인트 투 포인트 점검과 오버라이드 규율은 제어 커미셔닝에서 다룹니다. 이 페이지에서는 다른 작업, 즉 실시간 프로그램에서 고장을 찾는 방법을 다룹니다.

잘못된 출력에서 역방향으로 추적하기

초보자는 작성된 순서대로 시트를 읽으려 합니다. 왼쪽 입력에서 시작해 신호를 순방향으로 따라가며 블록을 하나씩 확인합니다. 꼼꼼한 방법처럼 느껴지지만, 고장까지 가는 가장 느린 경로이기도 합니다. 고장 난 시트도 대부분은 정상이기 때문입니다. 블록 하나만 잘못된 답을 내고 나머지 서른 개는 제 역할을 완벽히 수행합니다. 순방향으로 읽으면 중요한 블록에 닿기 전에 정상인 구십 퍼센트를 전부 검사하게 됩니다. 순방향은 시트를 학습하는 방법이지 고치는 방법이 아닙니다.

따라서 반대쪽 끝에서 시작하세요. 신고 내용에는 이미 잘못된 출력이 드러나 있습니다. 운전하지 않는 난방, 닫히지 않는 댐퍼, 해제되지 않는 경보가 그 예입니다. 해당 출력에 손가락을 대고 배선을 하나씩 상류로 거슬러 올라가며 매 단계에서 같은 질문을 하세요. 이 입력들을 고려할 때 이 출력이 맞습니까? 여기서 "맞다"는 단순히 블록의 레이블대로 계산된다는 뜻이 아니라 시퀀스가 필요로 하는 답이라는 뜻입니다. 답이 맞는 동안에는 블록이 정직하며 문제는 더 상류에 있습니다. 처음으로 “아니요”가 나오는 곳이 찾던 블록입니다.

시퀀스에 필요한 답과 레이블이 계산하는 답을 구분하는 것이 핵심입니다. 블록은 두 가지 방식으로 잘못된 답을 낼 수 있기 때문입니다. 연산 자체가 고장 나는 경우는 드뭅니다. 블록은 지시받은 계산을 항상 정확히 수행합니다. 흔한 원인은 잘못된 문장이 블록에 구성된 경우입니다. 방향이 반대로 설정된 비교기, 빠진 반전, 누군가 잘못 입력한 상수, 서로 바뀐 배선 한 쌍이 그 예입니다. 이런 블록은 자신의 질문에 언제나 충실히 답하지만, 질문 자체가 잘못되어 있습니다. 그래도 같은 추적으로 찾아낼 수 있습니다. 해당 단계에서 출력이 시퀀스가 분명히 필요로 하는 답과 어긋나고, 그보다 상류는 모두 타당합니다. 잘못된 답을 내는 블록이나 그 설정이 바로 손가락 아래에 있습니다.

이 규율을 따르면 두 가지 이점도 저절로 얻습니다. 잘못된 출력에 도달하지 않는 모든 분기는 이 추적에서 존재하지 않는 것과 같습니다. 아무리 의심스러워 보여도 살펴볼 필요가 없습니다. 또한 "맞다, 정직하다"고 판단한 각 단계에서는 정상 입력 위쪽의 전체 하위 트리를 조사 대상에서 제외할 수 있습니다. TRUE인 운전 허가 경로 하나만 보면 이를 만든 체인 전체가 정상임을 알 수 있습니다. 역방향 추적은 단순히 반대쪽 끝에서 시작하는 방법이 아니라 가지치기 전략입니다. 한 단계씩 이동할 때마다 시트가 작아집니다.

눈앞의 값에서 스캔이 의미하는 것

기능 블록 기초에서는 시트의 실행 방식을 설명했습니다. 제어기는 소스부터 의존성 순서로 모든 블록을 초당 여러 번 평가하며, 이 주기를 스캔이라고 합니다. 피드백 배선에는 이전 스캔의 값이 전달되므로 루프가 스스로를 끝없이 쫓지 않고 해결됩니다. 이것이 작동 메커니즘입니다. 실시간 시트 앞에서는 이 메커니즘이 실제로 관찰할 수 있는 세 가지 현상으로 나타납니다.

값은 순서대로가 아니라 함께 움직입니다. 한 번의 스캔 안에서 비교기, 게이트, 출력으로 이어지는 전체 조합 체인이 모두 결정되고, 화면은 제어기의 스캔보다 훨씬 느리게 다시 그려집니다. 값이 블록에서 블록으로 기어가듯 이동하는 모습을 볼 수 없으며, 그런 모습을 기다려서도 안 됩니다. 여기서 중요한 진단 원칙이 나옵니다. 한 체인에서 다른 입력도 TRUE인 AND에 TRUE가 들어가는데 출력은 FALSE인 것처럼 값들이 서로 맞지 않는다면, 화면에서 전파 지연을 본 것이 아닙니다. 관찰할 수 있는 전파 지연은 없습니다. 해당 블록에 실제 문제가 있으며 “아니요”를 찾아낸 것입니다.

피드백은 값의 시점을 정직하게 보여 줍니다. 래치에 Q TRUE가 표시되는데 S 입력이 FALSE이면 초보자에게는 고장처럼 보입니다. 켜는 입력이 없는데 출력이 켜져 있기 때문입니다. 하지만 이는 시트에서 가장 정상적인 모습입니다. Q는 상태이며, S는 수천 번의 스캔 전이라도 한 번만 TRUE였으면 됩니다. 자체 출력으로 되돌아가는 모든 배선도 같은 방식으로 읽습니다. 설계상 정확히 한 스캔 전인 이전 스캔 값을 전달합니다. 추적이 상태를 갖는 블록에 도달하면 질문의 시제가 바뀝니다. "이 입력들을 고려할 때 이 출력이 맞습니까?"가 아니라 "이 입력들과 정당한 과거 상태를 고려할 때 맞습니까?"를 물어야 합니다. 래치에서는 현재 S 값만 보지 말고 무엇이 S를 동작시켰을 수 있는지 확인하세요.

입력을 강제 지정하는 것은 가장 빠르게 실행할 수 있는 실험입니다. 전체 시트가 매 스캔마다 결정되므로 강제 지정한 값은 다음 화면 갱신 전에 모든 하류 블록으로 전파됩니다. 온도를 다섯 도 높이면 비교기, 래치, 게이트, 출력이 한꺼번에 상태를 드러냅니다. 플랫폼에서 이를 강제 지정(force), 오버라이드(override), 서비스 제외(out of service) 중 무엇이라고 부르든 수동적인 판독을 능동적인 시험으로 바꿉니다. 이 입력이 X라면 시트가 올바르게 동작합니까? 그렇다면 고장은 강제 지점의 상류로 이동하고, 아니라면 하류에 남습니다. 빠르게 수렴하는 이진 탐색입니다. 모든 강제 지정을 기록하고 모두 해제하는 안전 규율은 커미셔닝에서 사용하는 오버라이드 규율과 같습니다. 해당 학습 자료의 오버라이드 절이 기준이며, 재실 건물에서는 더 엄격하게 적용해야 합니다.

로직 패턴 식별: 블록 다섯 개를 이름 하나로

글을 읽을 때 글자 하나씩 읽지 않고 단어로 읽습니다. 시트도 마찬가지입니다. 이 장의 각 학습 자료에서는 실제 시트에 하나의 단위로 반복해서 나타나는 블록 묶음을 설명했습니다. 묶음의 이름을 알면 블록 다섯 개가 단어 하나로 줄어듭니다. 블록 마흔 개짜리 시트는 배선으로 연결된 여섯 개나 일곱 개의 패턴이 되고, 추적은 블록 사이가 아니라 패턴 사이를 이동합니다. 익숙한 패턴 안에서는 각 핀이 어떻게 동작해야 하는지 이미 알고 있으므로 중요한 단계는 패턴이 맞닿는 경계입니다.

퍼미시브 체인 · 운전 허가

운전 확인 → AND → AND → … → 운전 허가

모든 안전 조건과 운전 확인 신호를 차례로 AND로 묶습니다. FALSE 경로 하나면 운전 허가가 사라지므로 추적은 "FALSE 경로 찾기"입니다.

래치 + 수동 리셋 · 기억

고장 → S · 버튼 → R · Q가 트립 유지

고장이 한 번 발생하면 사람이 확인할 때까지 래치가 유지됩니다. 따라서 S가 FALSE인데 Q가 TRUE이면 블록 고장이 아니라 패턴이 정상 동작하는 것입니다.

밴드 경계 클러스터 · 불감대

SP ± DB → GT / LT → SR 래치

더하기와 빼기로 경계를 만들고, 비교기 두 개가 감시하며, 래치는 그 사이를 유지합니다. 채터링하는 대신 경계를 지날 때 한 번만 전환하는 온도조절기입니다.

운전 확인 시간창 · 기동 실패

CMD AND NOT(상태) → TON → 래치

지령은 있지만 운전 확인 신호가 없으면 타이머가 시작됩니다. 정상 기동은 설정시간 전에 완료되고, 시간창보다 오래 지속되는 실패만 경보로 래치됩니다.

리셋 연산 체인 · 스케줄

입력 → MUL → ADD → LIMIT

조건값으로 계산한 설정값, 즉 범위 제한을 적용한 y = mx + b입니다. 직접 입력한 것처럼 보이는 설정값이 계속 움직인다면 이 패턴일 가능성이 큽니다.

모드 전환 · 설정값 두 개, 배선 하나

모드 비트 → SELECT: 재실 / 비재실

불리언 값으로 두 값 중 흘려보낼 하나를 선택합니다. SELECT를 연쇄 연결하면 세 개 이상의 모드를 만들 수 있습니다. 두 값보다 먼저 선택 비트를 추적하세요.

각 패턴은 이 장의 별도 학습 자료에서 자세히 다룹니다. 불 대수 로직 및 래치에서는 체인과 래치를, 비교기 및 불감대에서는 밴드 경계를, 타이머 및 지연에서는 운전 확인 시간창을, 설정값 연산 및 리셋 스케줄에서는 리셋 연산 체인과 SELECT를 설명합니다. 여기서는 이름만 알면 됩니다. 그 이름이 있어야 다음 절의 추적이 가능하기 때문입니다.

추적 예제 — 추운 아침, 난방 불능

한 장의 시트에서 전체 방법을 적용해 보겠습니다. 공기조화기의 난방 요구 로직입니다. 프로그램은 이번 가을에 설치되었고 오늘은 처음으로 실제 추운 아침이며, 신고 내용은 간단합니다. 실내 온도는 65 °F이고 계속 떨어지는데 난방이 켜지지 않습니다. 직접 작성한 프로그램이 아닙니다. 블록보다 패턴을 먼저 읽으세요. 위쪽에는 밴드 경계 클러스터가 있고, 이는 68 °F 설정값을 중심으로 난방 온도조절기를 만듭니다. 왼쪽 아래에는 두 운전 확인 신호로 구성된 체인이 있습니다. 게이트 AND가 두 패턴을 난방 지령으로 결합하고, 에서 갈라진 작은 분기는 트립 램프를 구동합니다. 블록 열다섯 개이지만 패턴 네 개와 짧은 분기 하나입니다.

파란색 배선은 아날로그 값을, 녹색 배선은 TRUE 디지털 신호를, 회색 배선은 FALSE 디지털 신호를 전달합니다. 실시간 편집기와 같은 색상입니다.

단계 1 — 증상에서 시작합니다. HEAT는 OFF입니다. 입력은 게이트 출력 하나뿐이고 그 값은 FALSE입니다. FALSE 입력을 그대로 반복하는 출력 블록은 정직하므로 상류로 이동합니다. 단계 2 — 게이트입니다. 두 경로 중 운전 허가는 TRUE이고 요구는 FALSE입니다. TRUE와 FALSE를 입력받은 AND가 FALSE를 출력하는 것은 정상입니다. 여기서 가지치기의 이점이 나타납니다. TRUE인 운전 허가 경로를 보면 아래쪽의 체인 전체를 조사 대상에서 제외할 수 있습니다. 한눈에 상태 ON, OK, 운전 허가 성립을 확인하고 다시 읽지 않습니다. FALSE 경로를 따라갑니다. 단계 3 — 래치입니다. S와 R이 FALSE이고 Q도 FALSE입니다. Set도 Reset도 되지 않은 래치는 이전 스캔 상태를 반복합니다. S가 한 번도 동작하지 않았다면 정상입니다. 래치는 정직하며, 질문은 S가 왜 동작하지 않는지로 상류를 향합니다. 단계 4 — Set 경로입니다. 입력은 실내 온도 65와 하한 밴드 경계 67입니다. 시퀀스가 이 블록에서 필요로 하는 답은 "실내 온도가 밴드 아래로 떨어졌으므로 난방을 요구한다"이며 65는 분명히 67보다 낮으므로 답은 TRUE여야 합니다. 하지만 블록은 FALSE라고 답합니다. 첫 번째 “아니요”입니다. 이제 배선이 아니라 블록을 읽으세요. 레이블은 A > B입니다. 블록은 "65가 67보다 큰가?"라는 잘못된 질문에 언제나 정확히 답합니다. 난방 온도조절기의 Set 경로에는 A < B가 필요합니다. 위쪽 Reset 경로를 보면 같은 블록이 올바르게 사용되었습니다. 클러스터를 만든 사람이 Reset 비교기를 먼저 만들고 Set 경로에 복사한 뒤 복사본의 방향을 바꾸지 않은 것입니다. 문자 하나가 빠진 결함을 네 단계 만에 찾아냈습니다.

추적하지 않은 부분을 세어 보세요. 체인은 단계 2에서 한눈에 정상으로 판단했고 개별 블록을 따라가지 않았습니다. 아래쪽 동결 트립 램프 분기는 경로에 전혀 없습니다. 모든 배선이 회색이라 시트에서 가장 눈에 띄는 함정입니다. "죽은" 배선을 찾는 초보자는 이곳에 먼저 도달하지만, 회색은 FALSE라는 뜻일 뿐이며 정상인 트립 램프는 바로 FALSE여야 합니다. 이 분기의 어떤 것도 난방 출력에 도달하지 않으므로 추적할 필요가 없습니다. 순방향으로 읽으면 소스 다섯 개에서 출발해 정상인 시트 전체를 거쳐야 잘못된 블록 하나에 닿습니다. 역방향 추적은 블록 네 개만 확인했습니다.

마지막으로 기억할 점이 있습니다. 반전된 비교는 날씨에 따라 시퀀스의 동작 방향 전체를 뒤집습니다. 추운 아침 난방을 막은 같은 오류가 지난주의 온화한 오후에는 과열을 일으켰을 것입니다. 67 경계보다 높은 곳에서는 어디서나 S가 동작하고, R이 마침내 반대하는 69를 지나도 Set 우선형 래치에서는 S가 이깁니다. 조건에 따라 반대로 나타나는 증상은 방향이 뒤집힌 비교일 가능성이 큽니다. 수정 자체도 작은 검증 과정입니다. 블록을 A < B로 바꾸고 S가 TRUE가 되어 래치가 Set되고 난방이 시작되는지 확인하세요. 그다음 해제 동작도 검증하세요. 작동을 확인하지 않은 수리는 공구가 들어간 가설일 뿐입니다.
