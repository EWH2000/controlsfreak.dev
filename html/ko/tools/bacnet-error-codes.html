BACnet 오류 코드 디코더 BACnet

장치가 요청을 거부하며 돌려준 번호를 실제 오류 원인, 즉 오류 클래스와 코드, Reject 사유 또는 Abort 사유로 해석합니다.
BACnet 요청이 실패하면 장치는 세 가지 중 하나로 응답합니다. BACnet-Error(오류 클래스와 오류 코드), 메시지 형식이 잘못되었음을 알리는 거부 사유를 담은 BACnet-Reject, 또는 트랜잭션이 종료되었음을 알리는 중단 사유를 담은 BACnet-Abort입니다. 받은 응답 종류를 선택하고 번호를 입력해 의미를 확인하거나, 아래의 전체 참조 표를 필터링하세요.

입력란에는 예제가 미리 채워져 있습니다. 확인하려는 번호로 수정하세요.

Error, Reject, Abort 비교

세 응답 모두 "아니오"를 뜻하지만 실패 지점이 다르며, 그 차이로 확인할 위치를 알 수 있습니다. BACnet-Error는 요청 형식이 올바르고 서비스도 실행되었지만 장치가 요청 내용을 정확히 이해한 뒤 거부했다는 뜻입니다. 오류 클래스(범주)와 오류 코드(구체적인 사유)를 반환합니다. 현장에서 가장 흔하며 unknown-property, write-access-denied, value-out-of-range 등이 해당합니다.

BACnet-Reject는 요청이 그 단계까지 도달하지 못했다는 뜻입니다. 의 형식·인코딩이 잘못되었거나 장치가 구현하지 않은 서비스를 사용해, 서비스가 실행되기 전에 프로토콜 계층에서 폐기되었습니다. BACnet-Abort는 이미 시작된 트랜잭션이 도중에 종료되었다는 뜻이며 거의 항상 세그멘테이션, 타임아웃 또는 장치의 버퍼·리소스 부족이 원인입니다. Reject는 메시지를, Abort는 전송이나 장치 용량을 확인하라는 신호입니다.

오류 클래스와 코드 읽기

BACnet-Error에는 항상 두 값이 함께 들어 있습니다. 클래스는 문제를 device, object, property, resources, security, services, vt 또는 communication 범주로 나누고, 코드는 해당 범주 안의 구체적인 메시지입니다. 실제 조치는 대개 코드를 기준으로 하며 클래스는 어느 하위 시스템에서 오류를 발생시켰는지 알려 줍니다. 같은 코드 번호가 둘 이상의 클래스에 사용될 수 있으므로 두 값을 모두 디코딩하세요.

클래스 0–63과 표준 코드 범위는 ASHRAE가 관리합니다. 클래스 64 이상은 벤더 전용 오류이며 의미는 제조사 문서에 있습니다. 어느 제조사인지 벤더 ID 조회에서 확인할 수 있습니다. 객체 참고 자료에서는 이 오류들이 가리키는 객체 유형과 속성을 설명합니다.
