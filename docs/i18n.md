# Internationalization

controlsfreak.dev publishes English at its existing URLs and localized pages
under a locale prefix, for example `/education/bacnet-basics.html` and
`/ko/education/bacnet-basics.html`. English remains the default locale. The
site never redirects from a browser-language guess: visitors choose a language
explicitly and every translated page links back to its exact counterpart.

## Architecture

The implementation keeps behavior in one place while making omissions fail at
build time:

- `html/_data/i18n.js` defines public locales and short, shared interface copy.
- `lib/i18n.js` owns locale-aware paths, canonical URLs, and strict message
  lookup. There is no fallback to English for a missing localized message.
- `html/i18n-runtime.njk` emits the small browser-side `window.CFI18n` helper.
- `html/<locale>/` contains thin translated page templates. A translated page
  extends its English source and replaces only the `content` block, so page
  styles and behavior cannot fork by language.
- Page-specific runtime messages use matching `pageMessages` frontmatter in the
  English source and translated child. Inline scripts read them through
  `CFI18n.page(key, values)`.
- `html/_data/quiz-translations/<locale>/` overlays stable question and choice
  IDs without copying quiz behavior or answer keys.
- `html/_data/glossary-translations/<locale>.js` overlays the stable glossary
  term IDs without copying matching behavior.

The `i18nPageGuard` collection in `.eleventy.js` verifies the route bijection,
source relationship, content structure, internal links, machine-readable
fields, FAQ and defined-term data, runtime-message keys, interpolation tokens,
and source hashes. A source edit therefore fails the build until its translation
has been reviewed against the new source.

## Adding a language

1. Add one locale record and a complete shared-message catalog in
   `html/_data/i18n.js`. Shared keys and interpolation placeholders must match
   English exactly.
2. Add `html/<locale>/<locale>.11tydata.js` with the locale code and create the
   locale search-index template.
3. Add one thin child for every English canonical page. Preserve element order,
   IDs, classes, `data-*` attributes, form values, units, formulas, code,
   protocol identifiers, and link targets; localize internal links with the
   locale prefix.
4. Add the quiz and glossary overlays. Overlay keys are contracts: never
   translate or renumber them.
5. For every parent content block, record the SHA-256 value expected by
   `sourceContentHash`. Pages with `pageMessages` also record the matching
   `sourceMessageHash`.
6. Add the locale to `completeLocales` in
   `html/_data/i18nStatus.js` only after every canonical route is present.
7. Run `npm run build`, `npm test`, `npm run prose-lint`, and
   `npm run metric-lint` before opening a pull request.

## Korean editorial conventions

Korean copy uses a professional `-합니다` style. Instructions use `-하세요`
only when the reader must take an action. A term is introduced in Korean with
its common English abbreviation when that helps a technician recognize labels
in controllers, drawings, or standards; protocol names, object/property names,
codes, formulas, and units remain unchanged.

The project consistently uses these domain terms:

- HVAC: `난방·환기·공기조화(HVAC)` on first use, then `HVAC` where clearer
- AHU: `공기조화기(AHU)`
- BAS: `건물 자동화 시스템(BAS)`
- DDC controller: `직접디지털제어기(DDC)`
- hydronics: `수배관 시스템`
- two-way / three-way valve: `2방 밸브` / `3방 밸브`
- closely spaced tees: `근접 배치 티`
- psychrometrics: `습공기 상태 해석`; psychrometric chart: `습공기선도`
- humidity ratio: `절대습도(함습비, W)`
- economizer: `외기냉방(economizer)`
- commissioning: `커미셔닝(기능 성능 검증)`
- proof: `운전 확인 신호`
- deadhead: `체절운전(deadhead)`; short cycling: `단주기 운전`
- floodback: `액냉매 유입(floodback, 액백)`
- pump head: `양정`; refrigeration head pressure: `응축압력`
- return air: `회기(RA)`; return water: `환수`
- valve authority: `밸브 영향도(authority, β)`
- wiresheet: `와이어시트`

When an established field label is more recognizable in English, the Korean
explanation accompanies it instead of replacing the identifier. For example,
BACnet `Present_Value`, Modbus function codes, `AUTO / HAND / OFF`, and alarm
codes remain exact so the localized page still matches equipment interfaces and
vendor documentation.

## Translation review checklist

- Compare the localized page with the complete English source, including SVG
  titles/descriptions, table captions, callouts, examples, FAQ frontmatter,
  inline-script states, validation errors, and empty or failure states.
- Recalculate examples independently; do not translate identifiers embedded in
  formulas, protocol frames, register maps, or code samples.
- Keep factual scope identical. Do not add advice, claims, or safety guidance
  that is absent from the source.
- Exercise all interactive branches in both unit systems and at keyboard and
  mobile breakpoints.
- Search the rendered locale output for unexpected English prose. Brand names,
  standards, identifiers, abbreviations, and deliberate bilingual first-use
  terms are expected exceptions.
- Verify reciprocal canonical and `hreflang` links, localized search results,
  structured data, social-card metadata, and language-switch targets.
